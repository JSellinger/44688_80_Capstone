\subsection{Data Transformation}
Transformation will be the initial setup of our data and we should ideally manipulate the data in such a way that it is read to load into our database or be directly used in our ML pipeline. Transformation is less important when working with small datasets, as we are less limited by memory or CPU bottlenecks, hence why the entire dataset will be loaded. If we had pursued an ELT method we could have pulled in only what we needed and then manipulated it but for visibility into the reasoning for certain transformations, choices, and better data exploration we are making a deliberate choice to do pull the entire dataset and perform transformations on the entire set or as needed. Given that information we will perform minimal transformations beyond standard data cleaning and normalization by droppping missing critical values, which are those that we are using or targeting, explicitly type cast certain variables, and any feature engineering that may be necessary.

    We will want to drop rows that are missing only non-critical values. For example, we are targeting lead time for our ML algorithm so we want to avoid dropping this unnecessarily or any of the attributes that we believe we might use. In this case, from my real world experience, we will likely use Latitude, Longitude, Customer City, Customer Country, order date (DateOrders), Order Item Total, Product Category Id, Shipping Mode are likely to help us train an ML model to predict Days for Shipping (real).\

    After dropping critical rows that have null values we will want to type set anything so that everything is normalized. For example, dates and times are passed as strings instead of true date times so we will need to type set shipping date (DateOrders)

    \begin{lstlisting}[language=Python, caption={Data preprocessing, type casting, and targeted cleaning}]

    def clean_critical_data(df: pd.DataFrame) -> pd.DataFrame:
        """
        Cleans critical columns: strips headers, fixes data types (numeric & date),
        and drops rows with missing/invalid values across ALL selected columns.
        """
        # Create an independent copy to prevent modifying the original input
        df_clean = df.copy()

        # 1. Clean column header whitespace
        df_clean.columns = df_clean.columns.str.strip()

        # 2. Define numeric columns
        numeric_cols = [
            'Latitude', 
            'Longitude', 
            'Order Item Total', 
            'Product Category Id', 
            'Days for shipping (real)'
        ]
        
        # 3. Fix wrong data types (converts bad text like 'N/A' or corrupt strings into NaN)
        for col in numeric_cols:
            df_clean[col] = pd.to_numeric(df_clean[col], errors='coerce')

        df_clean['order date (DateOrders)'] = pd.to_datetime(
            df_clean['order date (DateOrders)'], 
            errors='coerce'
        )

        # 4. Drop any rows missing values across ALL columns in the DataFrame
        df_clean = df_clean.dropna()
        
        print(f"Rows before: {len(df)} | Rows after: {len(df_clean)}")
        print(f"Columns before: {len(df.columns)} | Columns after: {len(df_clean.columns)}")
        return df_clean
    \end{lstlisting}

\subsection{Feature Engineering}

    We will perform some basic feature engineering now that we done some basic normalization of the dataset. Feature engineering for ML will allow us to test different types of ML algorithms. Most standard Skikit-Learn models cannot use categorical variables so we need to engineer a column so that they are categorical. Examples of the Scikit-Learn models that we might use are regression, random forest, and decision trees. ML models that I have not explicitly used but that can take categorical variables natively are modles that convert them to integers on the fly such as LightGBM or CatBoost. We will not be using or testing either of these for this project.

    We will show an example of turning the variable 'Shipping Mode' into an ordinal variable rather than categorical but we can apply the same method to all categorical variables. Turning categorical data into ordinal data does have some rules such as importance where the relationship is meaningful. \cite{GeeksforGeeks1} In the below case, we assigned it based on priority.

    \begin{lstlisting}[language=Python, caption={Ordinal encoding of Shipping Mode based on delivery priority}]
    # Define ordinal ranking dictionary (higher number = faster priority)
    shipping_mode_order = {
        'Standard Class': 1,
        'Second Class': 2,
        'First Class': 3,
        'Same Day': 4
    }

    # Apply ordinal mapping to create a new engineered feature
    df['Shipping_Mode_Ordinal'] = df['Shipping Mode'].map(shipping_mode_order)

    # Verify mapping result
    print(df[['Shipping Mode', 'Shipping_Mode_Ordinal']].drop_duplicates())
    \end{lstlisting}

    As an important note, we have explicitly said "ordinal" but categorical data can also be turned into "nominal" where the priority or importance does not matter. SciKit also comes with some built in encoders to transform items for us should we not want to assign every variable ourselves. \cite{ScikitlearnOrdinalEncoder}

\section{Mathematical Formulations}

WORK IN PROGRESS

To account for lead time variability ($\sigma_L$) and demand variability ($\sigma_d$), the dynamic Safety Stock ($SS$) and Reorder Point ($ROP$) are calculated as:

\begin{equation}
    SS = Z \times \sqrt{\bar{L} \cdot \sigma_d^2 + \bar{d}^2 \cdot \sigma_L^2}
\end{equation}

\begin{equation}
    ROP = (\bar{d} \times \bar{L}) + SS
\end{equation}

Where $\bar{d}$ represents average daily demand, $\bar{L}$ is the predicted mean lead time, and $Z$ corresponds to the target service level factor.
